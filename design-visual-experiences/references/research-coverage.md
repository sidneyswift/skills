## How to interpret a source

- **Retrieved creator text:** what the author described, requested or claimed. A detailed prompt specifies an intention; it does not prove the result met it.
- **Inspected source:** implementation details read at a pinned revision. Reading code is not running it or reproducing a benchmark.
- **Observed behavior:** a specific live interaction or sequence actually exercised. The earlier pass observed selected live demos; this pass tested the bundled original studies. The source videos were not all watched.
- **Adapted guidance:** independently written mechanisms, build steps, tuning and prompts. These are practical starting points to verify in the new project, not verbatim creator instructions.

All 1,095 retrieved original post bodies were reviewed. Novel replies were filtered for prompt, technical and resource signals; all 472 resulting previews were screened and selected longer technical bodies were read. The remaining replies are preserved in the separate research archive but were not all manually read. Index tags, engagement, model names, speed and ‘one-shot’ claims are not quality validation.

The packaged catalog preserves IDs, links, discovery metadata, keyword terms, retrieval status, prompt signals and selected creator follow-ups. Raw API responses and long creator prompts stay in the separate research archive; they are not copied into the skill. Use the canonical source for exact prompt wording, and respect its reuse terms. New prompts in the atlas are labeled adaptations.
