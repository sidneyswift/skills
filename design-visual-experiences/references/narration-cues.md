# Retiming motion around spoken meaning

Use for narrated diagrams, character explainers and kinetic type when the voice take may change. A launch follows a verb; a reveal lands on the named idea; a reaction comes after the listener understands it. Anchor a few decisive moments and preserve breathing room between them.

The engine looks up a word's start/end within a line and supports selecting a repeated occurrence. The voice script converts line-local word times into film times; the renderer injects those times into the film. The example uses word cues for a flight and camera move. It also demonstrates a static wiring defect: its local helper's third argument is an occurrence index, but calls pass decimal values resembling fallback seconds. Those non-integer occurrence lookups miss and fall back to zero. Treat this as a source-inspection finding, not a reproduced render failure. Its normalization also strips non-ASCII letters, which needs redesign for multilingual scripts.

## Original build recipe

1. **Give each spoken line a stable identity.** Store take revision, actual audio duration, and aligned word spans. Keep word times relative to the line; resolve them into film time only after placing the lines. Do not use array position as durable identity if lines can be inserted or reordered. Alignment is estimated evidence: listen to important cue words and correct their boundaries when needed.
2. **Describe cues by meaning with explicit fields.** Use line ID, token or phrase, integer occurrence, start/end edge and an optional time offset. A cue such as “second occurrence of open, start edge, anticipation 0.15 seconds” is less ambiguous than several positional numbers. Use Unicode-aware matching and language-appropriate tokenization. A repeated phrase or punctuation change must not silently select a different event.
3. **Compile the cue table before rendering.** Resolve each anchor against the chosen take. Missing or ambiguous anchors should yield a visible authoring error; allow a fallback only when deliberately supplied and flagged for review. Check finite times, integer occurrence, valid word spans, chronological event order and positive motion intervals. If an anticipation would precede the shot, change the staging or lead-in explicitly. Do not quietly clamp every error to time zero.
4. **Derive all dependent motion from the resolved cues.** Use one arrival event for the path endpoint, camera settle, reaction delay and impact sound. For a fixed path between launch and arrival, map the valid interval to normalized progress; evaluate authored motion from that progress. If a new voice take leaves too little travel or reading time, insert a pause or reblock the shot. Automatically speeding up every action preserves timestamps but can destroy comprehension.
5. **Rebuild after each narration change.** Re-align changed takes, place the lines, resolve cues and regenerate captions and downstream events from the same timeline. Invalidate dependent previews. Preserve a chosen final hold and audio tail when calculating film duration; a voice-over that extends beyond a fixed film length is a delivery error to resolve, not merely a warning to ignore.
6. **Review cause and meaning together.** Listen while watching the important launch, reveal and reaction moments, then inspect neighboring frames. Test a slower take, a removed anchor, repeated words, an inserted line and non-English text. Scrub out of order for deterministic authored films. Check the final mix: mechanically matching a word boundary does not guarantee an expressive beat.

Expose anticipation, reaction delay, minimum readable hold, minimum travel time and final tail. Avoid anchoring every decorative movement: a few semantic events should organize the scene while secondary motion follows a consistent rhythm. Use [production timing](production.md) for render clocks and [timing/presentation contracts](timing-and-presentation.md) for player synchronization.

**Adapted prompt:** Create a narrated [diagram or short film] with a small cue sheet connecting decisive motion to spoken meaning. Resolve explicit line, phrase, occurrence and edge fields before rendering. Make missing anchors visible. Re-record one line and demonstrate that its dependent action, camera settle, captions and sound still agree. Preserve reading time and intentional pauses; report which audio/visual moments were actually checked.

For a visible character guide, use [embodied narrator direction](embodied-narrator.md) to connect looks, pointing and expression phases to the same resolved cues.
