# Workspace OS v0.11.1 work-continuity baseline

## Verdict

FAIL — v0.11.1 has no stable ordinary-work lifecycle or canonical cross-domain handoff interface.

Fresh-agent continuation itself passed in all three samples. The failure is narrower and important:
each workspace improvised a different structure, none implemented the proposed managed-work contract,
and success depended on a capable operator reconstructing or inventing the missing interface.

## Frozen input

- Skill: `packages/workspace-os-v0.11.1.zip`
- Scenario: `workspace-os/evals/scenarios/work-continuity/`
- Date: 2026-07-28
- Method: one fresh builder and separate fresh operators per sample

## Sample 1 — continuity named in the builder prompt

Run: `workspace-os/evals/runs/2026-07-28-work-continuity-red/`

The builder created a domain-specific continuity system:

- canonical state: `initiatives/decision-memory/README.md`;
- separate continuation state: `initiatives/decision-memory/handoff.md`;
- stage state: `delivery/02-discovery/decision-memory.md`.

The second operator resumed without repeating the completed investigation and advanced the recorded
experiment. This sample demonstrated that v0.11.1 can build strong continuity when the kickoff names
the requirement directly. It was rejected as the RED control because the prompt supplied the desired
outcome.

## Sample 2 — continuity omitted, but work matched the core domain entity

Run: `workspace-os/evals/runs/2026-07-28-work-continuity-red-unprompted/`

The product-team builder inferred `initiatives/` as its core entity. The memory effort therefore
became a normal domain initiative:

- state: `initiatives/agent-decision-memory/README.md`;
- experiment plan: `work/evaluations/2026-07-28-decision-retrieval-baseline/plan.md`;
- stage pointer: `roadmap/01-intake/agent-decision-memory.md`.

The second operator found the same initiative and did not repeat the initial inspection. This was
also not a clean test of cross-cutting work because the requested effort fit the generated domain's
existing entity and pipeline.

## Sample 3 — cross-cutting system work outside the domain pipeline

Run: `workspace-os/evals/runs/2026-07-28-work-continuity-red-crosscutting/`

The consulting builder correctly reserved `clients/` and `pipeline/` for consulting state. The
internal memory R&D effort was instead filed as dated one-off/system work:

- `work/product-decision-memory/2026-07-28-baseline-and-first-experiment/README.md`;
- `experiment-01.md`;
- `experiment-01-results.md`.

There was no canonical `work/product-decision-memory/README.md`, package metadata, shared work
contract, status vocabulary, closure date, or archive view. The fresh operator still continued
successfully by following `PROGRESS.md`, knowledge links, and filesystem search.

## Cross-sample findings

### Behavior that passed

- Fresh-agent continuation succeeded 3/3.
- Completed investigation was not repeated 3/3.
- Each operator left an evidence-linked next action.
- The generated root brain and domain records provided useful continuity primitives.

### Contract that failed

- Three samples produced three incompatible work topologies.
- No sample created `work/AGENTS.md` or a `work/CLAUDE.md` adapter.
- No sample created and used a Workspace OS setup package.
- No sample implemented the shared status set
  `active | blocked | paused | review | complete | cancelled`.
- No sample had one machine-checkable package record with evidence-gated closure and durable-value
  disposition.
- No sample provided a derived work index/archive view.
- The doctor did not validate package IDs, lifecycle fields, handoff freshness, or closure evidence.

## Interpretation

The baseline does **not** support the claim that v0.11.1 is incapable of handoff. It supports the
user's narrower report: work organization is improvised, domain-dependent, and hard to predict across
workspaces and agents.

The v0.12.0 change should therefore standardize a small interface without replacing the effective
domain continuity that v0.11.1 already produces. The GREEN eval must preserve fresh-agent continuation
while reducing topology variance and adding deterministic lifecycle checks.
